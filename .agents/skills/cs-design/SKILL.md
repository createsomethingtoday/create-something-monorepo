# CREATE SOMETHING design

Resolve paths from the repository root. Begin with the user's problem, required
capabilities, owning brand, and approved baseline. Record an initial approach
before searching for precedent; references inform the solution's tradeoffs.

1. Read the owning surface and its Canon contracts. Use
   `packages/dotfiles/codex/skills/canon-design-review/SKILL.md` for substantial UI
   work. Add `packages/dotfiles/codex/skills/canon-public-surface/SKILL.md` for
   public pages. Use the available `$canon-motion-craft` skill when interaction
   or explanatory motion is material. Client-owned brands retain their identity.
2. Follow the design-review skill's Mobbin-first research protocol when the
   change needs interaction precedent. Compare actual distinct examples,
   explain what each supports, and translate useful behavior through Canon and
   Performance Lab. Use curated TASTE evidence when it answers a visual question.
   If access or relevant coverage is missing, state the gap and continue with
   permitted source evidence and prototypes. Preserve required capabilities.
3. Keep the existing visual language unless a new direction is authorized.
   Prioritize task sequence, hierarchy, clarity, and feedback. Use motion to
   explain a state or relationship; inspect playback before making timing claims.
4. Compare the rendered result with the baseline. Exercise the affected states,
   keyboard/focus behavior, accessibility, and responsive layout. For material
   Agency public-page work, use the owning surface's six-width contract:
   `320, 390, 768, 1024, 1025, 1440`. Check relevant reduced-motion, no-JS,
   overflow, hash navigation, and interrupted-motion behavior. Scale the pass to
   the changed behavior; a literal copy fix does not require a new research study.
5. Fix evidenced findings and rerun affected checks. Preserve a compact reference
   record and before/after evidence for the reviewer. Report what was directly
   viewed or exercised and what remains uncertain. Mark perceptual quality
   untested if the actual output could not be viewed; tokens and test counts
   cannot substitute for that observation.

This entry point supplies design judgment and verification. Promotion follows
the owning release policy and `.agents/skills/cs-release/SKILL.md`; a prototype
or reference approval alone does not authorize publishing.
