# Newsletter distribution

Use [the distribution runbook](../../../docs/guides/NEWSLETTER_DISTRIBUTION_PLAYBOOK.md) for channel roles, source review, publication receipts, and outcome review. Apply it to the requested stage; a draft or analysis request does not authorize publication.

Start with the current public artifact and its owning source. Use CTX for prior decisions and discarded approaches, then verify any public claim against current source, live pages, and receipts. The `.io` archive and signup, `.agency` service evidence, and Substack are distinct destinations with distinct subscriber lists.

For shared or delegated work, keep the scope and acceptance in Linear. Use the `create-something` Paperclip instance for agent execution, following [paperclip-instance-operations](../paperclip-instance-operations/SKILL.md). Pass the source card and claim limits with each assignment. Record draft, approval, publication, and outcome as separate states; read back a public URL before claiming a post is live. On an uncertain write, check for an existing post before retrying.

For newsletter email delivery or engagement metrics, follow [newsletter engagement review](../../../docs/guides/NEWSLETTER_ENGAGEMENT_RUNBOOK.md) and the owning delivery workflow. Distribution work alone does not authorize a send or subscriber import.
