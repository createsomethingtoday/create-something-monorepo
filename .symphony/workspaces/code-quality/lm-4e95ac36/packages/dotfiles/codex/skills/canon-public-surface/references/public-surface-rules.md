# Public Surface Rules

Use this reference when shaping public-facing pages in CREATE SOMETHING.

## Property Intent

- `.agency`: buyer trust, workflow infrastructure, control layer, operational leverage
- `.io`: research, papers, experiments, evidence, implementation patterns
- `.ltd`: canon, principles, philosophy, standards
- `.space`: practice, experiments, interactive systems, live demonstrations

## Preferred Devices

- instrument-style dashboards that explain a system
- artifact strips showing policies, runbooks, evals, or delivery evidence
- clear process lanes and escalation models
- diagrams that make governance and flow legible
- sparse but meaningful motion

## Anti-Patterns

- commodity startup language like "transform your business with AI"
- decorative gradients that have no semantic role
- generic app-store benefit grids
- trust badges used as decoration instead of evidence
- delight mechanics that make a serious control product feel unserious

## Hero Test

A strong CREATE SOMETHING public hero should make these clear quickly:

1. what system or workflow is being addressed
2. why native tools are not enough
3. what artifact, control layer, or operating model is being added
4. what the next action is

## Editing Bias

When in doubt:

- choose the more legible layout
- choose the more operational copy
- choose the more inspectable proof
- remove the decorative flourish
