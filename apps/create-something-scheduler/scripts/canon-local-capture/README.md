# Canon consented local tab audio source

Desktop Google Chrome private unpacked extension. This is a manually operated, bounded consented meeting audio source for `canon-local-transcript.swift`. It captures only one authorized Zoom web-client meeting or exact official Google Meet URL in the dedicated Canon participant browser profile. All speakers join through other identities (including a host-only meeting), so their voices arrive as remote tab audio. The extension never accesses a microphone, requests video, uploads audio, injects into the meeting page or records in a background worker.

## Operator setup

1. Use the dedicated Canon Google Chrome participant profile. Ensure it is the intended meeting-participant identity. Load this folder through `chrome://extensions` → Developer mode → Load unpacked. No Chrome account synchronization or public store publishing is required.
2. Have the host announce the Canon Meeting Notes participant and obtain explicit consent from every host and guest before recording, including late arrivals. Use a visible participant name identifying the note taker. For Zoom, join using **Join from your browser**, then connect computer audio; the native Zoom application is not a tab-audio source. Zoom's browser join option may be disabled by the host. The extension does not generate Zoom's native recording announcement or recording indicator. Do not begin until everyone understands this separate local recorder. Keep the Canon participant's microphone disabled. All speakers must join elsewhere; local microphone audio is intentionally absent from this recorder.
3. With that dedicated joined meeting tab active, click the extension toolbar action. It opens a visible **separate control tab** bound to the source tab ID from that click. It is not an action popup and survives focus changes and the native save picker.
4. In the control tab, enter and save the authorized meeting reference. Zoom accepts HTTPS `zoom.us` or a syntactically valid subdomain ending in `.zoom.us`, with `/j/<9–11 digit meeting number>`, `/wc/<meeting number>/join`, or `/wc/join/<meeting number>`. The saved reference is always the same origin plus `/j/<meeting number>`; it contains no query or fragment. The documented embedded join-passcode query key is removed without retaining its value. Unknown or duplicate query keys fail closed; do not broaden the allowlist to get past an error. Google Meet retains its strict official meeting-code URL rule. Userinfo, nonstandard ports, fragments, lookalike domains and host-start routes are rejected. Capture must start from the already joined Zoom `/wc/` browser tab on the exact same origin and meeting number as the reference; an invite `/j/` launcher alone is rejected. Confirm the consent checkbox for each recording.
5. Press **Start consented recording**. Select a new `.wav` file inside an already private local folder, outside cloud synchronization and shared/repository paths. This happens before audio is opened. Chrome may ask to allow tab capture. The extension verifies the source tab ID, origin and meeting identity again, then starts audio capture. The control status says RECORDING. Return to the control tab whenever Stop is needed; leave that tab open. The normal source tab audio continues to play.
6. Press **Stop and save WAV**. It stops capture first, then finalizes a streamed 16-bit mono PCM WAV at the browser audio sample rate. Check the file locally before transcription, then `chmod 600 /explicit/private/path/meeting.wav`. The private parent must be operator-owned and mode 0700 for the Swift utility. Chrome's save picker cannot enforce Unix ownership or folder privacy; the operator must choose a suitable destination.
7. Run the Swift local-transcript utility with that exact audio path, meeting ID and `--host-consented`. Delete retained audio/transcript when the meeting retention period ends. Disable or remove this unpacked extension after use.

The local saved configuration contains only the sanitized meeting reference, not audio or join credentials. Do not copy invitation credentials into logs, handoffs or instructions. Stop and source navigation/close/track ending terminate the stream; source navigation, identity mismatch or an inaccessible source aborts the local write and discards captured audio. A normal source-tab close or audio-track end saves already accepted PCM while immediately rejecting new frames. An uncertain reload/navigation event overrides a simultaneous source-close save until file commit. Explicit Stop flushes the worklet tail with a one-second acknowledgement deadline before finalizing; a timeout preserves accepted audio and reports that the final tail was unavailable. A 60-minute hard limit stops and saves. Audio streams as 16-bit PCM into the selected local file; no full-meeting audio array is retained. Pending disk writes are capped at one second of PCM and the worklet has at most eight 4096-sample messages outstanding. Slow disk/controller processing stops capture and aborts the file. At 48 kHz an hour requires about 346 MB of disk; at 192 kHz about 1.38 GB. Ensure sufficient free local space before starting. The final WAV header is patched only on successful Stop or the hard limit. Closing the controller immediately ends capture and discards unsaved samples; do not close it in place of Stop. No persistent background recorder or restart handler exists. A supplementary half-second URL check fails closed if the source becomes inaccessible; if a second tab-list check confirms that the source tab is absent, it instead saves already accepted PCM, even if the close event has not arrived yet. Changing tabs is allowed: the recorder remains bound to the original tab ID, origin and meeting number. A same-meeting URL update containing only the supported embedded passcode state does not change this identity; a document reload still stops capture. Moving between Zoom origins is a source change even when the meeting number matches.

Only remote audio rendered in the dedicated participant tab is captured. A muted, disconnected or silent meeting can produce silence. This does not establish speaker identity or quality of transcription. The recorder mixes incoming browser audio to mono and does not perform diarization. Chrome may suppress tab playback during capture, so the extension explicitly routes the captured stream to the controller's audio destination to preserve playback. Use headphones and avoid playing the same meeting through additional devices nearby.

## Validation and limits

`node --test apps/create-something-scheduler/scripts/canon-local-capture/audio.test.mjs` checks official URL selection/rejections, deterministic WAV header/sample encoding, clipping, maximum sample count, extension permission limits and absence of network transport code. The manifest has only `activeTab`, `tabCapture`, and local `storage`; its extension CSP denies network connections. The service worker only opens the controller and never captures audio. There are no host permissions.

The browser lifecycle, Chrome stream-ID permissions, native save picker and actual Zoom/Meet audio must still be validated in the dedicated Chrome profile. No live meeting or microphone capture was performed during implementation. A synthetic WAV unit test is not live browser capture evidence. If Chrome rejects `getMediaStreamId` for this profile or control tab, stop and retain the error; do not add broad host access or switch to background recording.

## Zoom leave and room changes

Press **Stop and save WAV before leaving**, before opening another meeting or breakout room, or when consent changes. Then leave in Zoom. A normal source close or ended audio track saves already accepted PCM. An observed source reload, unknown URL state or origin/meeting change aborts the uncommitted file; a subsequent close does not override that uncertain-navigation decision. Changing focus to another tab is allowed. A same-document Zoom leave, disconnect or breakout transition may leave the URL and audio track alive: this extension does not inspect Zoom's page or participant roster and cannot reliably detect those states. The operator must stop explicitly. Do not equate a connected capture track or silence with an active, consented meeting. Rejoin and reconfirm consent in a new recording after any room change.

Official references: [Zoom Web App](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0064261) documents browser meeting paths; [Join from your browser](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0067293) explains the host-controlled browser option; [Zoom security explainer](https://media.zoom.com/download/assets/securing-zoom-meetings.pdf/1304947ab13d11eea071a2e0973c74dc) documents the alternate `/wc/join/` path; [Zoom developer forum](https://devforum.zoom.us/t/web-client-with-embedded-password-requires-passcode/31102) documents the embedded join-passcode query. No external Zoom meeting or mutation was used for this validation.
