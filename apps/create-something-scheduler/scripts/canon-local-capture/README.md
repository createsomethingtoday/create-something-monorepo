# Canon one-test local tab audio source

Desktop Google Chrome private unpacked extension. This is a manually operated, bounded internal-test audio source for `canon-local-transcript.swift`. It captures only one exact official Google Meet URL in the dedicated Canon participant browser profile. All speakers join through other identities (including a host-only test), so their voices arrive as remote tab audio. The extension never accesses a microphone, requests video, uploads audio, injects into Meet or records in a background worker.

## Operator setup

1. Use the dedicated Canon Google Chrome participant profile. Ensure it is the intended internal-test identity. Load this folder through `chrome://extensions` → Developer mode → Load unpacked. No Chrome account synchronization or public store publishing is required.
2. Have the host obtain everyone's explicit consent before recording. Join the single selected test using an official `https://meet.google.com/abc-defg-hij` URL. Keep the Canon participant's microphone disabled. All speakers must join elsewhere; local microphone audio is intentionally absent from this recorder.
3. With that dedicated Meet tab active, click the extension toolbar action. It opens a visible **separate control tab** bound to the source tab ID from that click. It is not an action popup and survives focus changes and the native save picker.
4. In the control tab, enter and save the exact test Meet URL. Only the exact official hostname and standard meeting-code path are accepted; credentials, ports, query strings and fragments are rejected. Confirm the consent checkbox.
5. Press **Start selected test**. Select a new `.wav` file inside an already private local folder, outside cloud synchronization and shared/repository paths. This happens before audio is opened. Chrome may ask to allow tab capture. The extension verifies the source tab ID and exact URL again, then starts audio capture. The control status says RECORDING. Return to the control tab whenever Stop is needed; leave that tab open. The normal source tab audio continues to play.
6. Press **Stop and save WAV**. It stops capture first, then writes a 16-bit mono PCM WAV at the browser audio sample rate. Check the file locally before transcription, then `chmod 600 /explicit/private/path/test.wav`. The private parent must be operator-owned and mode 0700 for the Swift utility. Chrome's save picker cannot enforce Unix ownership or folder privacy; the operator must choose a suitable destination.
7. Run the Swift local-transcript utility with that exact audio path, internal test ID and `--host-consented`. Delete retained audio/transcript when the test retention period ends. Disable or remove this unpacked extension after the test.

The local saved configuration contains only the selected Meet URL, not audio or credentials. Stop and source navigation/close/track ending terminate the stream; source navigation or close also attempts to save already captured audio. A ten-minute hard limit stops and saves. Closing the controller immediately ends capture and discards unsaved samples; do not close it in place of Stop. No persistent background recorder or restart handler exists. A supplementary half-second URL check fails closed if the source becomes inaccessible. Changing tabs is allowed: the recorder remains bound to the original tab ID and URL.

Only remote audio rendered in the dedicated participant tab is captured. A muted, disconnected or silent test can produce silence. This does not establish speaker identity or quality of transcription. The recorder mixes incoming browser audio to mono and does not perform diarization. Chrome may suppress tab playback during capture, so the extension explicitly routes the captured stream to the controller's audio destination to preserve playback. Use headphones and avoid playing the same meeting through additional devices nearby.

## Validation and limits

`node --test apps/create-something-scheduler/scripts/canon-local-capture/audio.test.mjs` checks official URL selection/rejections, deterministic WAV header/sample encoding, clipping, maximum sample count, extension permission limits and absence of network transport code. The manifest has only `activeTab`, `tabCapture`, and local `storage`; its extension CSP denies network connections. The service worker only opens the controller and never captures audio. There are no host permissions.

The browser lifecycle, Chrome stream-ID permissions, native save picker and actual Meet audio must still be validated in the dedicated Chrome profile. No live meeting or microphone capture was performed during implementation. A synthetic WAV unit test is not live browser capture evidence. If Chrome rejects `getMediaStreamId` for this profile or control tab, stop and retain the error; do not add broad host access or switch to background recording.
