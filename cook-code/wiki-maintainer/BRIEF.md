# Wiki maintainer acceptance

Local repository skill for maintaining guidance after a real correction or source change. Judgment tier. The existing company guide describes this loop, and the generated Atlas projection has its own integrity check. The baseline repository has no wiki-maintainer skill. Preserve existing local work. This run delivers to the repository workspace and exercises a draft social without external writes.

- A. An agent entering the company guide can find a valid repository skill, follow the original route, distinguish stale guidance from a missed instruction, and select the owning source or a justified no-edit result.
- B. A maintainer can give a fresh agent the original request without coaching, observe its output, evaluate current evidence and permissions, and make a bounded repair if it fails.
- C. The initial replay produces a new, locally reviewable social draft with caption, alt text, editable composition, final visual, project evidence and current design rationale. A reviewer checks claim, actual visual, and authority. Project choice is open.
- D. Repository links and skill format validate. Independent Sol 6.1 review checks the actual artifacts and a counterexample. No new service or deployment.

Baseline incident in the previous social exercise: the initial draft used a historical design before the operator called attention to newer projects and design. Source and permission checks are mandatory; metrics, deadlines and a background schedule are outside this trial.
