# Property Intent Funnel

Status: canonical public-property handoff contract

## Outcome

A visitor can enter any CREATE SOMETHING property, understand that property's job, take a useful action there, and move into the next appropriate surface without being forced into a calendar. The system supports both self-serve learning and an assisted path into governed delivery.

## Property ownership

| Property  | Owned job                                      | Appropriate next moves                          |
| --------- | ---------------------------------------------- | ----------------------------------------------- |
| `.ltd`    | Canon and operating principles                 | Research, practice, or standards                |
| `.io`     | Research and transferable evidence             | Workbench, guided learning, or practice         |
| `.space`  | Runtime validation and experimentation         | Research or practice                            |
| `.learn`  | Guided artifact-building                       | Workbench, Canon, or practice                   |
| `.agency` | Practice, qualification, and governed delivery | Practice, services, then booking when qualified |

The properties are not a fixed linear sequence. Each is a valid entry point with one locally owned job. The shared funnel presents adjacent moves based on visitor intent rather than pretending every visitor begins on `.ltd`.

## Action temperature

1. **Local:** let the visitor use the property they chose.
2. **Adjacent:** offer one next capability that reduces uncertainty.
3. **Practice:** use `createsomething.agency/practice` to map a named workflow, owner, boundary, and proof requirement.
4. **Book:** expose `/book` only from `.agency` surfaces where the workflow and accountable owner can be named.

Cold landing pages on `.ltd`, `.io`, `.space`, and `.learn` must not jump directly to `/book`. The existing `.agency` cold/warm/hot ladder remains the commercial conversion authority.

## Journey context

Cross-property handoffs may carry these query fields:

- `journey`: an opaque session identifier generated by first-party analytics
- `source`: the originating property
- `intent`: a bounded intent slug
- `stage`: the funnel stage
- `lane`: the product or delivery lane

The fields must contain no email address, name, free-form form response, authentication material, or other personal data. When Do Not Track or analytics consent disables tracking, the shared funnel does not append the journey identifier. Query context is validated before it is admitted to analytics metadata.

## Canon-owned implementation

- `packages/canon/src/lib/funnel/property-intent.ts` owns the five-property role and action contract.
- `packages/canon/src/lib/components/PropertyFunnel.svelte` renders the shared handoffs.
- `packages/canon/src/lib/analytics/client.ts` resumes valid first-party journey context.
- `packages/canon/src/lib/analytics/interactions.ts` emits `funnel_handoff` conversions with bounded metadata.

Properties may change their local copy and primary action, but must not fork the shared role, booking boundary, or journey-validation rules.

## Measurement

The north-star signal is a qualified workflow entering `.agency` practice with enough context to name the workflow and owner. Supporting measures are:

- local property action completion;
- cross-property handoff rate by source, intent, stage, and lane;
- practice engagement and workflow-map completion;
- qualified practice-to-book conversion;
- return visits that resume the same opaque journey.

Page views alone are not adoption proof. Initial implementation establishes the contract and instrumentation; a post-launch window is required before conversion performance can be judged.

## Verification

For every release that changes the contract:

1. Run the Canon funnel contract tests and all affected package checks.
2. Confirm no cold-property landing page links directly to `/book`.
3. Verify desktop and mobile rendering for all five properties plus `.agency/practice` and `/book`.
4. Follow a cross-property link, confirm bounded context survives reload, and confirm no personal data appears in the URL.
5. Verify Do Not Track or denied consent prevents the shared funnel from adding `journey`.
