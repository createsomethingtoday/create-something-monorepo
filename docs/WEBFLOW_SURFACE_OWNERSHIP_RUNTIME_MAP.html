Webflow posture Render UI, host entry points, embed apps, collect interaction.

The recurring implication: Webflow should present trusted state and workflow affordances, while CREATE SOMETHING should decide, execute, persist, and audit.

Public Creator Flows

The creator-facing system splits Webflow-hosted entry and iframe surfaces from the Cloud app logic, automation services, and durable evidence stores.

Webflow App logic Automation Data
Creator-critical state Auth, submissions, uploads, analytics, and profile flows rely on Cloud app routes and backend bindings.
Analyzer posture Analyzer output assists creators with validation and autofill. It is not reviewer approval.
Migration posture The SvelteKit dashboard is now a parity reference for the Webflow Cloud dashboard port.

Reviewer and Agent Flows

Reviewer work should route through bounded MCPs and evidence surfaces. Raw Airtable writes are not the normal review path.

Entry and judgment MCPs Evidence Data plane
Normal write path Template and app review writes should pass through the matching review MCP.
Evidence caveat Published-site analyzer jobs are default review evidence. Manual Designer diagnostics require explicit scope.
Approval boundary Reviewer agents should verify capability flags and receive explicit approval before writes.

Governance Code Components Boundary

Code Components should render the governance console, but policy, credentials, workflow state, and mutation authority belong behind Cloudflare routes and operator-only boundaries.

Webflow UI Cloudflare API Durable state Policy
Public preview rule Public webflow.io previews should remain read-only or local-state only.
Credential rule Internal API keys and token-bearing endpoints do not belong in Webflow props or browser code.
Share rule Library sharing is externally visible and should follow governance verification.

Flow Dependencies

Each public or reviewer workflow has a different failure surface. Triage should start from the flow and then move to package, runtime, binding, and evidence.

Creator dashboard

Runtime needs

  • Airtable API key and base ID
  • SESSIONS KV and UPLOADS R2
  • Resend or Knock login path
  • Optional analyzer and Turnstile secrets
Submission app

Runtime needs

  • Parent Webflow iframe shell
  • Airtable automation webhook envelope
  • Upload worker secret and route
  • Template analyzer API base
Review hubs

Runtime needs

  • Airtable PAT and base ID
  • MCP API key from Infisical
  • Reviewer directory mapping
  • Analyzer browser credentials and DO jobs
