First sample: install the local evidence tooling and document/run existing offline tests. This is maintenance and changes no application UI or external system. Record the tested repository revision, command exit status, output receipt and unavailable operational baseline. Feature and bug samples must come from actual prioritized Goldin work; do not invent a defect to fill the cohort.

Schedule: week 1 begins with confirmed technical ownership and baseline collection. Week 2 exercises the internal three-change cohort. Week 3 uses approved Goldin feature/bug/maintenance work. Week 4 reviews matched observations and decides continue/revise/stop using the template criteria. Dates and business metrics remain uncollected until real observations exist. The framework can be installed before those four weeks elapse.

Client communications, production cutover, payments, live Notion changes, calendar events and media release retain their separate owning approvals. No synthetic records should be written to external systems for this baseline. A review or CLI validation does not grant access.
