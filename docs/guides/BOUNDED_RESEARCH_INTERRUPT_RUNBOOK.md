# Bounded Research Interrupt Runbook

- **Status:** v1 internal runbook
- **Owner:** active lane operator
**Trigger:** a potentially useful reference appears while another lane is active

## Purpose

Keep valuable research from becoming invisible scope expansion or an abandoned
implementation checkpoint.

## Procedure

1. Record the active lane's current command, source state, and next proof before
   opening the research source.
2. Name one question and set a time limit appropriate to the decision.
3. Capture only the source, the observed pattern, its relevance, and one route:
   `adopt`, `test later`, or `archive`.
4. Treat `adopt` as a new tracked decision or task when it changes scope,
   authority, or release timing.
5. Return to the recorded active-lane checkpoint and continue its existing
   acceptance criteria.

## Guardrails

- A research source is not an implementation mandate.
- Do not promote a vendor claim, benchmark, or visual reference into production
  policy without first-party or controlled evidence.
- Do not leave a protected action open while researching an alternative.

## Receipt

```text
Active lane checkpoint:
Question and timebox:
Source:
Observed pattern:
Route: adopt | test later | archive
Follow-up owner or issue:
Return-to-lane confirmation:
```
