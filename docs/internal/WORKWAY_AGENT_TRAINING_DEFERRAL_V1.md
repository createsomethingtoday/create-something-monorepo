# WorkWay Agent Training Deferral v1

**Decision:** do not train or fine-tune a WorkWay model in this phase.

The present capability is an API and evaluation foundation, not a data-collection or model-training program. The deterministic graph, operations, evidence gates, and qualified-review requirements are still the truth boundary. Fine-tuning now would add a probabilistic component before the product can reliably measure whether a request was proposed, blocked, or escalated.

## Current approach

- Use versioned synthetic/public design-intent cases only.
- Execute the bounded Composer against the canonical graph and deterministic operation validator.
- Measure stable expected outcomes, source-free receipts, revision binding, and negative boundaries before any wider information access.
- Treat any later model as an intent/candidate assistant behind the same API; it will never become the geometry, evidence, or construction authority.

## Re-open criteria

Training can be considered only when all of the following are evidenced:

1. Stable request, receipt, proposal, and evaluation APIs across representative projects and revisions.
2. A permissioned, reviewed corpus with documented ownership, consent/data-use rights, retention/deletion, provenance, and per-project isolation.
3. A privacy/security review covering private documents, model-provider terms, access control, redaction, audit, incident response, and customer opt-out.
4. An evaluator baseline that identifies a material shortfall in deterministic intent coverage or routing, rather than a preference for model novelty.
5. Measured quality gates for correct proposal, safe block/escalation, hallucinated authority, source leakage, and regression on known fixtures.
6. Explicit user approval for the provider, budget, corpus, training/fine-tune method, retention, and deployment boundary.

Until then, expanding the synthetic evaluator and codified operations is the lower-risk, more informative path.
