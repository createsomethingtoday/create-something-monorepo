## Daily operation

On weekdays at 09:30 America/Chicago, spend up to 20 minutes listening and
responding. Read full conversations before joining them. Prioritize Codex and
Claude Code builders, MCP maintainers, and Webflow integration builders.

Aim for two or three useful replies when there is something specific to add.
A reply should contribute a verified example, diagnostic step, tradeoff, or
question that moves the discussion forward. No quota overrides relevance.
No generic praise, copied replies, mass mentions, cold DMs, follow churn,
engagement bait, invented experience, or coordination of artificial engagement.
Use public, non-client examples. Credit the original author. Link only when it
answers the question; a reply should remain useful without the link.

User approved implementing the reviewed plan, including routine public posts
and relevant community replies. This does not authorize private disclosures,
new commercial commitments, security accusations, paid promotion, or unrelated
account changes. Stop a specific action if a new approval boundary applies.

Use the browser's current signed-in account only after verifying @createsmthng.
Read the timeline and campaign receipts before publishing to avoid duplicates.
After a timeout or uncertain submission, inspect live state before retrying.
If authentication or source evidence is missing, record the blocker and skip
publication. Do not publish filler to make the calendar look complete.

Do not store private profiles or DM contents.

- Attributable workshop visits or tool use only if an existing consent-respecting

UTM labels make referral links identifiable; they do not prove events are
collected. Do not add pixels or infer installs from views or clicks. There was

Continue topics that create useful exchanges and actual use. Do not rank formats
from tiny or unequal-age samples. Weekly reports should include concrete
examples and a small adjustment, not just totals.

## Automation and stop condition

It publishes only due, verified editorial slots; future briefs are checked at
run time. It records receipts in Linear and notifies on substantive outcomes,
weekly reviews, failures, or required user action. Stay quiet when unchanged.

extend the experiment or claim visibility increased without observed evidence.
