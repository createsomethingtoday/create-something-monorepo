# Client support record fields

Create these records in the client's Linear project. This file describes the fields; it is not an accepted enrollment record. Do not put client device details, passwords, screenshots or session transcripts in the public repository.

## Client onboarding issue

- Client and authorized contact
- Engagement or scope reference; support operator
- Agreed support hours or response terms, if any
- Device label, owner and architecture
- RustDesk ID, visible only to authorized operators
- Kit version and SHA-256
- Client consent date and permitted work
- Installation, permissions and restart-to-Ready results
- Screen, pointer and typing test results
- Client-initiated quit and disconnection result
- Status: pending, accepted, suspended or retired
- Open issue, next action and owner

## Session issue or comment

- Client/device and operator
- Date, requested problem and agreed task
- Consent confirmed for this session
- Intervention category
- Actions and approvals; omit passwords and tokens
- Result and client verification
- PR, change record or rollback instructions when applicable
- Session ended and client quit confirmed
- Remaining work and next owner

## Offboarding record

- Device and effective date
- Client confirmed app quit and session ended
- Permissions removed or app uninstalled
- Permanent-password/startup-service exceptions resolved, if present
- Separate account access reviewed within the offboarding scope
- Evidence retained under the client's policy; owner confirmation

Do not mark a field passed before the underlying check occurs. Record “not tested” or the observed failure when appropriate.
