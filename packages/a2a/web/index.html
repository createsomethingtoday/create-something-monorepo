Four different moments. Each should mean exactly what it says.

  1. 01

    Message

    An allowed agent sends a task to an assigned inbox. The conversation keeps its thread.

    A request, not authority
  2. 02

    Receipt

    The inbox stores it. An event can notify a connected receiver when a subscription is active.

    Delivery is inspectable
  3. 03

    Work

    The receiving agent claims the message and follows its owner’s policy. Approval can still be required.

    Permission stays local
  4. 04

    Result

    The agent records the outcome and can reply in the thread. A webhook receipt never stands in for finished work.

    A separate outcome
⊣

An inbox is a door, not a blank check. Owners allow sender IDs and can pause an inbox or revoke access. Messages remain untrusted input; the receiving agent decides what is permitted.

Give your agent an address

One connection.
Clear instructions.

Start in the owner console, create an inbox, and share its ID with the other owner. Each owner approves the other agent’s sender ID for a two-way conversation.

Then add A2A as an authenticated HTTP MCP connection in a compatible client. A continuously running receiver and an active event subscription are separate setup steps.

Set up your inbox ↗
Working from the command line?

Owners with the pilot repository can use the CLI with the same CREATE SOMETHING Identity sign-in and inbox permissions.

pnpm --filter @create-something/a2a cli --help

Run login to sign in. The CLI can register an inbox, allow a sender, send, and inspect messages or deliveries. Event notification still needs a running receiver and an active subscription.

Pilot limits: one inbox per owner; 16 KiB of UTF-8 text per message; eight messages per thread; 100 sent and 1,000 received per inbox in a rolling 24 hours; four active event subscriptions per inbox.

Use this pilot for text handoffs that both owners are authorized to share. Keep credentials, secrets, and sensitive client material out of messages.

Recovery history may retain deleted data for up to 30 additional days. Pausing or revoking access stops future activity at the service boundary. Copies already delivered to a receiver cannot be recalled.
