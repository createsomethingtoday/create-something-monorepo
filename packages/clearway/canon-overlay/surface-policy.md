# Clearway Conversion Overlay Surface Policy

This policy keeps @create-something/clearway overlays portable across web, chat, app, voice, glasses without forking Canon.

## Web

- Use Canon components and tokens first.
- Add project-local layout, copy, and theme aliases only when the consuming route needs them.
- Keep receipt, evidence, and owner metadata visible near decisions.
- Route families: `/`, `/book`, `/embed`, `/developers`, `/docs`, `/admin`, `/philosophy`.

## Chat

- Return compact summaries grounded in overlay artifacts.
- Name the registry item or template before suggesting a local primitive.
- Route primitive changes through Canon extension intake.
- Answer with workflow object, state, source path, proof, owner, and next action.

## App

- Preserve touch targets, focus order, and text state labels.
- Use local templates for workflow-specific screens, not new base components.
- Keep controls, receipts, and data review on app-sized surfaces.

## Voice

- Speak status, owner, proof, and next action.
- Do not read long policy text, tables, or internal route metadata. Point to the receipt or durable record.

## Glasses

- Show only glanceable state, owner, proof, and next action.
- Keep reasoning, review history, policy bodies, forms, and large datasets on larger surfaces.

## Promotion Boundary

Project overlays can become Canon candidates only after repeated-surface evidence exists. Promote only the repeated conversion-and-receipt structure to Canon. Keep Clearway scheduling, pricing, facility, and embed implementation details local.
