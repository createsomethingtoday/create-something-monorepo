## Jev Passage Routing

```bash
node packages/database-layer/scripts/agent-wiki-route.mjs --query "Which operations require production approval?" > /tmp/wiki-route-request.json
```

Read the packet and pass its `request` object unchanged to the configured
Jev `evaluate` MCP tool only when `needsJev` is true. Save the tool response
as JSON to `/tmp/wiki-route-response.json`, then validate it:

```bash
node packages/database-layer/scripts/agent-wiki-route.mjs --packet /tmp/wiki-route-request.json --response /tmp/wiki-route-response.json
```

The CLI makes no network calls. It selects at most six passages, includes source
paths, line numbers, snapshot dates and hashes, and caps the Jev request at 20 KB.
The model is pinned to `jev-1.13.0`; the complete returned distribution and
candidate IDs are validated. Changed sources invalidate the packet. No match,
a tie, invalid output, timeout or service failure means ordinary source inspection;
retain all candidates and do not retry the advisory request automatically.
If only one candidate exists, inspect it directly; if none exists, broaden normal
repository search. Inspect the selected passage and its owning source before use.
Record elapsed time and whether inspection found it useful alongside the result;
confidence measures distribution concentration, not correctness or permission.
The result has `authority: advisory_only` and cannot authorize mutations or
prove freshness of live systems. Source age must satisfy the task's freshness
requirement independently of ranking.
