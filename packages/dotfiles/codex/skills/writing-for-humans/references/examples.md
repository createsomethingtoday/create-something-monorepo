# Transformation Examples

Use these examples to recognize the level of change each framework supplies. Preserve the actual evidence and safety boundaries of the source artifact.

## Operator Instructions

Before:

> The system uses a governed deployment architecture with several verification surfaces. Operators should ensure configuration readiness before initiating promotion.

After:

> Use this path to deploy a reviewed change to preview. First run `pnpm check`. Continue when it exits successfully. If it fails, stop and fix the reported package before deploying. Record the preview URL and smoke result in Linear; that comment is the completion proof.

The revision supplies an outcome, first action, expected result, recovery, and completion proof instead of asking the reader to infer the path from architecture.

## Report Opening

Before:

> During the quarter, the team reviewed onboarding feedback, inspected support volume, and analyzed completion behavior across the setup flow.

After:

> Simplify onboarding this quarter. Complaints rose after three setup steps were added, completion fell, and support requests increased.

The answer comes first. The evidence is grouped beneath the recommendation instead of recreating the discovery sequence.

## Sentence Repair

Before:

> The implementation of the proposal resulted in an improvement in performance.

After:

> The team implemented the proposal and improved performance.

The character becomes the subject and the actions become verbs. A real artifact would retain the measurement or limitation that defines `performance`.

## Technical Information Flow

Before:

> A substantial increase in processing speed was produced by the revised algorithm.

When the paragraph is about the algorithm:

> The revised algorithm substantially increased processing speed.

Choose the subject from paragraph context. Do not rewrite mechanically when the paragraph is actually about processing speed.

## Narrative Opening

> Small businesses increasingly depend on digital payments, and customers expect immediate transactions. But rural businesses often have unreliable internet access. Therefore, payment systems need an offline mode.

The movement is useful because the tension motivates the direction. A direct operator instruction would not need this narrative setup.
