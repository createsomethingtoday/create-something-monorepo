## Webflow Way Validator – Agent Context

Purpose: Validate Webflow projects/templates against the "Webflow Way" guidelines across Components, Typography, Variables, Styles, and Naming. Includes a Designer Extension for in-Designer validation and a Next.js API for crawl-based checks.

### Repository layout
- `src/app`
  - `page.tsx`: Minimal UI to submit a URL and display results (local debugging/out-of-Designer use)
  - `api/validate/route.ts`: Primary POST endpoint performing validation; accepts `{ url, designerVariables? }`
  - `layout.tsx`, `globals.css`: App shell and minimal styles
- `src/lib`
  - `analyzers.ts`: Core analyzers
    - `fetchSiteAssets(url)`: Fetch HTML + linked/inline CSS
    - `analyzeNaming(html)`: Detect dominant class naming scheme, outliers, combo class depth violations
    - `analyzeTypography(html, css)`: Placeholder text detection, percentage line-height usage, body font presence
    - `analyzeStyles(css)`: Baseline tag style presence (H1–H6, p, ul/ol, blockquote, figure, figcaption, a), :hover/:focus/:active presence, CSS variable usage
    - Designer-sourced checks live in `src/app/api/validate/route.ts`; keep `src/lib/analyzers.ts` focused on crawl/published-site helpers
  - `types.ts`: Shared types (`ValidationIssue`, `CategoryResult`, `ValidationResponse`)
- `extension` (Designer Extension)
  - `webflow.json`: Manifest (apiVersion 2, size large, publicDir public)
  - `public/index.html`: Panel UI – one-click "Validate This Project"; derives published URL from Designer context and calls API. If context unavailable, prompts for URL.
  - `public/variables.js`: Gathers variable collections and variables via Designer API (e.g., `webflow.getAllVariableCollections()`, `collection.getAllVariables()`); passes normalized payload to API as `designerVariables`.
  - `bundle.zip`: Generated by Webflow CLI bundling (upload this in Workspace > Integrations > App development)

### Runtime overview
- Designer UX:
  - User opens the extension and clicks "Validate This Project".
  - Extension attempts to read Designer context (for domains) and Designer Variables API data.
  - Extension POSTs to API `/api/validate` with `{ url: publishedUrl, designerVariables }`.
  - API performs crawl-based checks and variables analysis (if provided), returns category issues and summary.
  - Extension renders a concise report.

- Out-of-Designer UX:
  - Developer runs `npm run dev` and visits the UI at `/`.
  - Enters a URL to test; app hits the same API route and renders results.

### Build and publish
- Install deps: `npm install`
- Local dev: `npm run dev` (API base is `http://localhost:3000`)
- Production build: `npm run build`
- Bundle Designer Extension: from project root: `npm run bundle:ext` (or `cd extension && npx webflow extension bundle`)
- Upload `extension/bundle.zip` via Workspace Settings → Integrations → App development → publish extension version (5MB limit). Ensure Workspace admin + 2FA.

### API contract
- POST `/api/validate`
  - Request body:
    - `url: string` (required – published site URL)
    - `designerVariables?: { collections: Array<{ id: string; name?: string | null; variables?: Array<{ id: string; name?: string | null }> }> }`
  - Response: `ValidationResponse`
    - `categories`: Components (placeholder), Typography, Variables (analyzed if provided), Styles, Naming
    - `summary`: counts of errors/warnings/info and pass/fail categories
  - CORS: OPTIONS and POST enable cross-origin calls (used by Designer Extension to call local API)

### Validation logic mapping to guidelines
- Components (phase 2 – Designer APIs):
  - Validate presence and naming of Components and variants (Title Case), nesting/composition patterns, and props/slots/variants usage
- Typography (crawl now):
  - No placeholder text (e.g., lorem ipsum)
  - Prefer percentage-based line-height; detect potential text overlap risks
  - Primary font on body, secondary fonts on headings where applicable
- Variables (Designer API now):
  - Ensure variables exist for colors/typography/spacing; variable names Title Case with spaces; inspect collection variable modes when available; detect one-off variables for future rule
- Styles (crawl now):
  - Baseline tag styles for H1–H6, p, ul/ol, blockquote, figure, figcaption, a
  - State styles presence (:hover/:focus/:active); usage of CSS variables in baseline
- Naming (crawl now):
  - Detect dominant scheme (BEM, snake_case, kebab-case, camelCase, PascalCase); flag outliers
  - Limit combo classes per element to <= 4

### Extension → API payload enrichment
- The extension tries:
  - `webflow.getAllVariableCollections()`
  - For each collection: `collection.getAllVariables()`, `collection.getAllVariableModes()`, variable `getName()`, and mode `getName()` when available
- Normalized into `{ collections: [{ id, name?, variables: [{ id, name? }], modes?: [{ id, name }] }] }` under `designerVariables`.

### Configuration and size
- Manifest (`extension/webflow.json`):
  - `apiVersion: "2"`, `size: "large"`, `publicDir: "public"`.
  - Designer panel: right side, entry `index.html`.

### Known limitations and next steps
- Components checks require Designer Components API — planned:
  - Detect required components (Navbar, Footer, CTA) exist as Components
  - Validate naming conventions for Components and variants
  - Verify composition patterns (Header includes Logo/Nav/Button)
- Variables deeper checks:
  - Variable modes for responsive values (tablet/mobile) via `collection.getAllVariableModes()`
  - Grouping and ramp ordering (light→dark, small→large)
  - Detect one-off variables (usage frequency) when element styles are queryable
- Styles enhancements:
  - Detect unused classes (Designer-only)
  - Redundant property detection (e.g., nested left-aligned text)
- Typography enhancements:
  - Spelling/grammar checks for headings/paragraphs (opt-in)

### Operational notes for agents
- Paths include spaces; use quotes in shell commands.
- Avoid long-running processes in CI tools; build is quick (`next build`).
- When bundling from scripts, prefer `npm run bundle:ext` or `cd ".../extension" && npx webflow extension bundle` to avoid PATH issues.
- For Designer API calls, not all functions may be present in all contexts—guard checks and fail gracefully.
