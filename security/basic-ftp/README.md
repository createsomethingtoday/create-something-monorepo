# Scoped basic-ftp 6.2.1 upgrade

This separately reviewable change resolves GHSA-c475-qrg2-pj4r with the official npm 6.2.1 package, not a backport, renamed version or scanner exception. The upstream advisory identifies <=6.2.0 as affected and 6.2.1 as fixed: https://github.com/advisories/GHSA-c475-qrg2-pj4r.

The actual dependency route is Puppeteer 21.11.0 / puppeteer-core → @puppeteer/browsers 1.9.1 → proxy-agent 6.3.1 → pac-proxy-agent 7.2.0 → get-uri 6.0.5 → basic-ftp. The root pnpm override is scoped to `get-uri>basic-ftp`; standalone npm uses a nested get-uri override. Both pin 6.2.1. Existing unrelated lock resolutions remain unchanged. The latest get-uri 8.0.1 still requests basic-ftp ^5.3.1; updating it would not fix the advisory and would change other dependencies. There is no compatible upstream parent update established here.

The official package remains CommonJS, supports Node >=10, and retains Client/access/lastMod/list/downloadTo/close used by get-uri. Node 20 (standalone Docker runtime) and Node 22 qualification are required. Compared with 5.3.1, v6 defaults `allowSeparateTransferHost` to false, rejects mismatched PASV hosts, improves TLS-session handling and verifies local-file upload length. The get-uri consumer downloads streams; it does not use local-file uploads. The safer passive-host default is retained, not overridden. Servers requiring a different passive data host are not claimed compatible; such configurations require separate review. Real FTP/FTPS services and TLS-session-resumption behavior were not tested here, and no credentials were used.

`provenance.json` records the official npm tarball integrity, verified from the downloaded package, and SHA-256 of every distributed JavaScript file. The installed verifier checks those bytes at every reachable basic-ftp installation, rejects other versions, and locates the actual get-uri consumer before running tests. Clean workspace and standalone installations are required; a version string alone cannot satisfy the gate.

The loopback-only synthetic fixture exercises get-uri's exact download bytes, MDTM metadata and cache rejection, MLSD listing fallback, missing-file and authentication rejection, and same-host PASV fallback. A mock passive-host rejection test proves no new socket is created for a foreign host. The malformed Unix listing regression runs in a child with a five-second ceiling so a parser regression cannot hang the qualification process. It also asserts ordinary Unix listings still parse. This is bounded compatibility/security evidence, not universal FTP server acceptance.

Run `node security/extract-zip/verify-installed.mjs <installation-root>` after installation. The existing policy gate runs it for both the root workspace and a fresh standalone npm installation. All scanner findings, severity thresholds, remaining vulnerabilities and final human-review requirements remain unchanged.
